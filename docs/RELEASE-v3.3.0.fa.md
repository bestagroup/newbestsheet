# گزارش انتشار v3.3.0

تاریخ: ۲۰۲۶-۱۰-۱۹. مبنا: 2995209 (main).

## دامنه تحویل

اصلاح معماری بخش صورت مالی و گزارش، تعریف مشترک دامنه پورتفوی فعال، رفع ناسازگاری آخرین دوره و مانده تعهد، اصلاح تست‌های قدیمی و ایجاد CI. تغییر دیتابیس تولید، تصویب چندمرحله‌ای، مهاجرت مالکیت صورت مالی و بازنویسی کامل سامانه در این تحویل انجام نشده‌اند.

## اعتبارسنجی محلی

- PHP 8.3.6، Laravel 12.61.1 و PHPUnit 11.5.56.
- نصب وابستگی‌ها از composer.lock؛ بدون ارتقای پکیج‌ها.
- suite: **۹۳ آزمون، ۵۲۷ assertion، بدون خطا، شکست یا risky** روی SQLite حافظه‌ای.
- syntax: ۲۵۱ فایل app و tests، بدون خطا.
- کامپایل Blade و cache مسیرها موفق.
- آزمون‌های جدید شامل آخرین دوره مدرن، تقدم نوع دوره در تاریخ یکسان، مقدار ناموجود، عدد بزرگ، سند تکراری شرکت، اضافه‌پرداخت، منع جابه‌جایی سند و اجرای migration پس از ایجاد ناقص اجزا هستند.
- نتیجه MySQL، مرورگر واقعی، بار و هم‌زمانی چند اتصال در اجرای محلی تأیید نشده است. CI برای SQLite و MySQL تعریف شده؛ وجود فایل CI به‌تنهایی به معنی موفقیت اجرای آن نیست.

## استقرار

1. تغییرات و ADR-001 را مرور و نسخه پشتیبان دیتابیس و اسناد را کنترل کنید.
2. کد tag نسخه را دریافت کنید و `composer install --no-dev --prefer-dist --optimize-autoloader` اجرا کنید؛ .env و APP_KEY قبلی حفظ شود.
3. این نسخه migration جدید ندارد. اگر نصب از نسخه قدیمی‌تر است، migrationهای معوق را ابتدا روی نسخه آزمایشی دیتابیس بررسی کنید.
4. `php artisan optimize:clear` و سپس cacheهای مورد استفاده محیط را بازسازی کنید؛ در صورت استفاده از queue worker، `php artisan queue:restart` اجرا شود.
5. گزارش را با داده‌های سالانه، فصلی، شرکت خارج‌شده و شرکت فاقد صورت مالی کنترل کنید. جدول پروژه‌ها اکنون نوع آخرین دوره را نیز نمایش می‌دهد.

Rollback این تغییرات کدی با برگشت به نسخه قبلی انجام می‌شود؛ برای بازگرداندن schema قدیمی، migrationهای تاریخچه تجاری را rollback نکنید. هیچ ادعای تأیید نهایی تولید یا صحت داده‌های سرور عملیاتی در این گزارش وجود ندارد.
