# ADR-001 — مرزهای دامنه و گزارش مالی

وضعیت: پذیرفته‌شده در v3.3.0، ۲۰۲۶-۱۰-۱۹.
مبنای بازبینی: main در 29952090e3d7b44a784c6bd2ba328090f813213c.

## تصمیم معماری

برنامه یکپارچه Laravel حفظ می‌شود. تغییر فعلی، بازآرایی تدریجی بخش مالی و گزارش است؛ تبدیل کل برنامه به Clean Architecture یا پیاده‌سازی کامل DDD ادعا نمی‌شود. سرویس‌های دامنه موجود، مرز تراکنش عملیات حساس را نگه می‌دارند؛ Controller مسئول HTTP و Form Request مسئول اعتبارسنجی ورودی است. برای Eloquent لایه Repository عمومی جدید اضافه نشده است.

## تغییرهای اجرایی

- `Project::activePortfolio()` تعریف واحد گزارش پورتفوی فعال است: مراحل ۱۴ تا قبل از ۲۰، ردنشده. `currentApplications()` طرح ردنشده قبل از مرحله ۶ را تعریف می‌کند. scopeها ستون‌ها را qualify می‌کنند و شروط OR را گروه‌بندی می‌کنند تا دامنه دسترسی قبلی نشکند.
- گزارش، نمودار هیئت‌مدیره و بخش‌های مالی/پورتفوی داشبورد از scope مشترک استفاده می‌کنند. شمارنده‌های کلی طبق نیاز محصول همچنان مستقل از فیلتر و شامل کل سامانه‌اند؛ اطلاعات مالی در دامنه دسترسی کاربر باقی می‌مانند.
- `FinancialStatementService` مرز تراکنش ایجاد/ویرایش/حذف صورت مالی است. قفل پروژه پیش از رکورد صورت مالی گرفته می‌شود. ثبت business audit در همان تراکنش است؛ خرابی audit تغییر مالی را rollback می‌کند. انتقال سند بین پروژه‌ها ممنوع است.
- یکتایی واقعی همچنان با constraint دیتابیس تضمین می‌شود. خطای یکتایی هم‌زمان به خطای اعتبارسنجی قابل نمایش تبدیل می‌شود. سرویس ورودی اعتبارسنجی‌شده می‌گیرد؛ مجوز ماژول همچنان در middleware است.
- دسترسی نگهداری سوابق تاریخی پس از خروج حفظ می‌شود؛ «پورتفوی فعال برای گزارش» با «قابل نگهداری بودن سند تاریخی» یکی نیست.
- انتخاب آخرین صورت مالی به `LatestStatementSelector` منتقل شد: تاریخ نزولی، و در تاریخ برابر سالانه سپس فصلی سپس legacy. این اولویت، سیاست انتخاب است و بیانگر قابلیت جمع‌زدن انواع دوره نیست.
- در جمع شرکت‌ها، سند تکراری همان شرکت/تاریخ/نوع کنار گذاشته و گزارش می‌شود. مقدار ناموجود صفر نیست؛ کارت جمع مبالغ معلوم است و پوشش داده و ناهمسانی دوره‌ها نمایش داده می‌شود. این کارت صورت مالی تلفیقی نیست.
- جدول پروژه‌ها به‌صورت پیش‌فرض آخرین سند از همه انواع دوره را می‌خواند. فیلتر صریح نوع دوره حفظ شده است. endpoint و سری‌های قدیمی تجمیعی برای سازگاری همچنان مبنای legacy پیش‌فرض دارند؛ مقایسه جدید شرکت‌ها مستقل و دارای تفکیک نوع دوره است.
- مانده تعهد منفی در جدول و جمع گزارش حفظ می‌شود و اضافه‌پرداخت پنهان نمی‌شود. فیلتر تاریخ پرداخت می‌تواند دامنه جمع قدیمی گزارش را محدود کند؛ کارت‌های بالای صفحه تجمعی هستند و این تفاوت در راهنمای صفحه مشخص است.

## Trade-offها و محدودیت‌ها

انتخاب آخرین دوره ممکن است انواع متفاوت را بین شرکت‌ها جمع کند؛ هشدار نمایش داده می‌شود و مدیر باید برای مقایسه هم‌دوره از نمودار تفکیک‌شده استفاده کند. در صورت وجود چند سند هم‌تاریخ و هم‌نوع، انتخاب دلخواه آخرین id انجام نمی‌شود. مهاجرت مالکیت صورت مالی از پروژه به شرکت در این نسخه انجام نشده؛ نیازمند تطبیق داده و تصمیم درباره چند طرح یک شرکت است.

مدل‌های قدیمی و نام‌گذاری‌هایی مانند Financial_statement برای جلوگیری از تغییر ناخواسته روابط و API حفظ شده‌اند. همه سرویس‌ها به DTO مستقل از HTTP تبدیل نشده‌اند. برخی سری‌های قدیمی هنوز float و تبدیل null به صفر دارند؛ مرجع جدید مقایسه هیئت‌مدیره و جدول دقیق از آن‌ها متمایز است.

## اقدامات بعدی

1. مهاجرت مرحله‌ای مالکیت صورت مالی به شرکت و حفظ project references.
2. ثبت ابتدا/انتهای دوره و مبنای مستقل/تجمعی صورت فصلی.
3. چرخه تصویب، قفل نسخه و اصلاحیه صورت مالی؛ تأیید دومرحله‌ای پرداخت.
4. تفکیک Read Model گزارش و حذف محاسبات قدیمی پس از بررسی مصرف‌کنندگان endpoint.
5. تست رقابت واقعی چند اتصال MySQL، آزمون مرورگر و اندازه‌گیری Query با حجم واقعی.
6. بازبینی record-level access در حوزه مالی و تعریف رسمی سطح اختیار نقش‌ها؛ توسعه چندسازمانی پروژه جداگانه است.
